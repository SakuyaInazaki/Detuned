### A2. 关闭 AA02：生成和运行时不能对同一 DDL 得出不同定义

当前 generate/check/test 的三个提取器丢弃索引键的 collation/desc 和 FTS 描述。运行时还写死 BINARY/ASC、固定 FTS 列与 tokenizer。这并未满足完整来源约束。

选择一个简单方案，使**当前/历史结构描述包含运行时真正比较的属性**，或由明确的自动一致性约束保证它们：

- 普通表保留已有列、类型、NOT NULL、PK 顺序、FK 绑定/动作等定义。
- PK/UNIQUE/必需索引包含完整 key 项、列绑定、顺序、collation、ASC/DESC、unique 与 partial；当前不支持表达式键时明确拒绝，不能生成时丢掉表达式再视为普通列。
- FTS 的模块、列/索引标志、配置属于版本描述的一部分，来源同样可追溯到该版本 DDL。
- V2 绑定当前 schema.sql；V1 绑定冻结历史源，保持已支持旧布局。当前变化不能偷偷改变 V1。
- 生成/检查/正式一致性测试复用同一明确定义，避免继续三份手抄提取器。可新增少量共享 helper，不需要新依赖或迁移框架。
- 运行时消费构建产物，不依赖源码目录或构建时临时库；`applyMigrations` 继续使用已有 DDL 常量。

验收使用隔离源码副本，真实产品 schema.sql 不为测试而改变：

1. 修改 named index 的 collation/方向，或 FTS 列索引标志：要么生成描述同步跟随、运行时认可该生成定义，要么生成/一致性检查明确拒绝该不受支持源变化。不能两脚本都说成功，运行时却拒绝自己生成的结构。
2. 修改一个允许的普通列属性，例如 NOT NULL：正常生成/同步通过，V2 更新，V1 不变；这是 AA04 的正例，不可通过一律拒绝源变更来蒙混过关。
3. 故意改坏生成描述，再运行真正的同步命令，必须非零；修复/重新生成后再次检查通过。单纯 `expect(objectA).not.toEqual(objectB)` 不算命令验证。
4. 完整输入生成并编译后移除 src，再导入产物、建立临时库并执行运行时结构校验，结果正确。
