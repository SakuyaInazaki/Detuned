## A. 先修公共契约（F03、F04）

1. 修正 publish/relate/review 工具 schema 的交集冲突：当前合法参数会被 additionalProperties:false 的分支拒绝；MCP inputSchema 根级还缺少 type=object。保留严格判别联合语义，用目标 SDK 接受的表达形式。
2. 将 protocol schema 真正连接到 HTTP body/query/params/headers 验证；坏字段、未知属性、缺少幂等键、越界长度和非法 kind/role 返回稳定 400/422，不写入数据、不变成 500。领域层重复执行关键不变量。
3. 初始帖子、普通帖子、修订采用一致的类型规则。claim/proposal 必填条件，failure 范围与证据状态，summary 引用等不能因 structured 缺失而跳过。字节上限按 UTF-8 计算。
4. 为真实构建后的 MCP stdio 服务加入工具发现和至少一次合法/非法调用测试；不是另造一个简单 InMemory 服务来替代。未实现 review 等能力不应伪装为可用工具。

## B. 修授权和脱敏（F01、F02、F06）

1. 每个操作同时满足 token capability、token 空间范围、当前成员角色与对象可见性；只读 token 禁止发帖。`/me`、`/spaces` 在分页前应用同样的范围限制。
2. 脱敏目标必须属于 URL 的空间。跨空间 target_id 返回 404，目标数据、索引、事件均不变。管理路由不得直接绕过 core 操作存储。
3. 脱敏应覆盖全部已实现读取路径，包括 revisions、thread 概要、context、搜索、幂等重放。只存对象引用的幂等记录不能含正文。处理已有 result_ref 中的历史副本，迁移须保护数据，不得建议用户删除数据库。
4. 补齐 M1 必要的凭据撤销、成员停用/角色变更操作；确保既有凭据立即失权。角色命名与规范统一，未知角色拒绝；不要提前宣称 verifier 模块已实现。
5. 变更状态、权限版本、事件、幂等记录在适当的同一事务内完成。不能只依赖客户端、路由层或缓存做最终授权。

## C. 修幂等和帖子原子性（F05、F08）

1. 幂等作用域包含实际目标资源。相同键和正文分别写 T1/T2 时不能静默返回 T1 的结果；按 docs/04 的目标 operation 分开处理。
2. HTTP 不以 req.id 自动替代缺失幂等键。若 CLI/client 生成键，在发送前持久记录，所有重试复用。
3. initial_post 复用事务内帖子创建逻辑，保存 refs、类型字段、统一内容 hash 和事件；无效初始帖子导致整个主题创建回滚。未实现附件不能静默丢掉 artifact_ids，可明确拒绝后留待 M2。
4. 补测同目标同键同内容、同键不同内容、不同目标、换 session、响应丢失、事务中注入失败和两个冲突请求。旧版本引用不可漂移，重复重试不增加业务事件。

## D. 修已暴露的事件与恢复行为（F07、F09、F10）

1. 去掉公开固定 token secret；使用实例随机持久密钥或数据库随机句柄。ACK 的实际推进位置取自服务端持久 batch，校验 actor/space/consumer/batch/版本/ACL epoch，不能信任客户端 through_seq。checkpoint 也要绑定身份与空间。
2. 不同过滤条件不得复用同一 subscription；真正实现 thread_ids 和 event_types 筛选，并保留空匹配批次的确认语义。重投同一待确认批次；旧 ACK 不回退进度；越权或伪造进度拒绝。
3. 实现真正的迁移版本记录与一份 DDL 来源，为当前无版本记录的 baseline 提供有完整性检查的升级方式。
4. init 必须取得数据目录锁并原子创建身份/凭据；重复初始化不得隐式生成新管理员。serve 对未初始化目录必须给出明确 init 指引，或者可靠地交付一次性凭据；不能生成后丢弃。
5. 用文件型 SQLite 验证关闭/重开后的数据、引用、事件和幂等恢复；补实际进程异常退出后的锁恢复测试。恢复机制不能无条件删除活进程的锁。关服务、关库完成后才释放锁。
6. 不扩展完整 M3 的备份/导入/长轮询平台；但已公开使用的错误路径必须修复或关闭并标注。
