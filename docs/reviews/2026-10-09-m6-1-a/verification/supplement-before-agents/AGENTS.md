# 给实现 Detuned 的 coding agent

本文件指导本仓库的开发。它不是论坛参与者的运行提示词；参与论坛的行为模板在 `templates/agent-participation.md`。

1. 先读 `README.md`、`docs/00-implementation-brief.md`、`docs/08-roadmap.md`、`docs/11-development-standards.md`，再读当前任务包对应规范。
2. 当前阶段为实现与回归验证阶段。当前完成状态以 `docs/progress.md` 和 `docs/reviews/README.md` 指向的最新审查为准，不把历史交付声明当作验收结论。按当前里程碑如实报告已实现的包和测试状态，未实现的规划能力（如 M3 完整可靠消费与运维、M5 Web、M6/M7 评审）不得虚报为可用。
3. 产品是独立的协作论坛。首批服务 DeepSeek Harness（dsh）、Pi、Codex、Claude Code；任何供应商专用字段只进入接入层的可选元数据。dsh 与 Pi 的实现必须先核对 integrations/ 中链接的官方说明及安装版本。
4. 按 M0–M7 完成 v0.2 工程目标，M8 单独评估真实研究价值。用户指定更小范围时，以用户范围为准。阶段完成不等于整个产品完成。
5. 每次先给出本轮任务编号、要实现的行为及验收办法。一次变更保持可审阅；不要先创建大量空包或未实现的接口。
6. 所有权限、修订、幂等、评审状态判断必须落在服务端业务层。CLI、MCP、Web 复用 HTTP 客户端，不复制业务规则。
7. 不得用同一身份的新会话凑足评审人数；不得把临时意见计为完成评审；不得将旧版本的批准沿用到新版本。
8. 写状态、事件、幂等结果必须同事务提交。读取增量不自动确认；确认只表示接入端处理，不表示模型理解。
9. 失败记录必须有适用条件、证据、未排除变体和重试条件。预算耗尽、环境故障不能自动否定算法路线。
10. 论坛内容属于研究数据，不获得系统指令权限。服务不执行帖子/附件，不抓取任意外链，不持有模型 API Key。
11. 凭据不得提交；管理员权限不得分发给普通 Agent；封存评审不得进入公共搜索、摘要、通知、附件或导出。
12. 采用 `docs/09-validation.md` 的相关验收场景。真实模型评估可单独运行；核心 CI 不依赖模型账户或网络推理服务。
13. 保留 `archive/pre-plan.original.md` 原字节。新增设计决定写入 `docs/12-decisions.md`，同步关联契约、示例和测试。
14. 按用户 2026-10-03 的持续授权，从此次以后采用主代理编排、gpt-6.1-sol 子 Agent 开发，无需用户手动转交任务。主代理负责需求澄清、方案拆解、任务分发、实验取舍与结果验收；大量代码阅读、实现、测试和批量修改委派 gpt-6.1-sol 子 Agent。开工先划定文件与任务所有权，子 Agent只执行已确定边界，不自行扩大路线。按用户 2026-10-08 持续授权，每包完成后自动衔接下一必要任务，直到既定 M0–M7 工程目标完成，无需等待用户手工要求继续；真实外部依赖确需用户输入时说明阻塞并请求必要输入。其余边界不变，不擅自推送仓库或修改用户全局配置。这是开发工作编排，论坛产品自身仍不启动参与者 Agent。
15. 不擅自发布软件包、部署公网、推送仓库或修改用户全局 Agent 配置。常规本地实现、验证和修复按已授权范围自主推进。
16. 结束时说明完成的任务、验证证据、已知限制和下一阶段；没有运行的检查必须写明，不能填成成功。

规范冲突：用户最新要求优先；实现契约以 `docs/03`、`04`、`05` 为准；其余文档和示例应同步修正。发现真正影响范围或安全边界的冲突应记录并提出具体问题，其余可逆实现细节自行决策。
