## R3-A：权限和状态变更必须经过同一个业务边界

覆盖 R3-F01/F02/F05，主要入口为 auth、redaction、membership/ACL、event ACK。对应反例 T04/T05/T08。

必须实现：

1. **统一范围语义。** `allowed_space_ids=[]` 表示不允许任何空间，`['*']` 表示通配；显式范围只允许交集。core、列表、/me、context、帖子读写、订阅/poll/ack 一致判断，不能列表隐藏而直接 URL 可访问。记录该语义及旧凭据处理决定，升级不静默扩大权限。保持空 capability 禁止读写、只读禁止写、已禁用身份/凭据拒绝等现有行为。
2. **新增最小 RedactionService 或等价 core 业务方法。** 路由只负责解析、调用、响应，不再直接 storage.createRedaction。权限和空间归属、幂等请求、完整 affected_revisions、内容/索引清理、审计、`post.redacted` 事件与结果引用在一次事务中提交。尚未支持的附件脱敏不借机实现 M2。
3. **脱敏可重试。** 同 actor/space/目标/键/内容重试，返回同一 redaction_id，不新增审计或事件；同作用域同键不同内容返回 409。结果只保存必要引用，不缓存被脱敏内容。复用现有事务和幂等结构，但为新操作提供明确结果类型，不能靠任意对象 fallback。
4. **历史修订完整。** 审计列出全部受影响 revision，不能只取 listPostRevisions 默认第一页。脱敏后正文、摘要、标题、tags 等受保护内容不经当前已实现的读路径或幂等返回。允许保留的引用/哈希按协议明确定义。
5. **ACL 失效一致。** 已过期消费者的 poll 和 ack 采用相同的当前 ACL epoch 检查；失效 ACK 不推进 ack_seq，不标记 batch 已确认，不清掉待处理批次。合法重复 ACK 成功、伪造/其他 consumer ACK 拒绝、旧 ACK 不回退。最终校验与状态变更处于同一事务。

必须运行的验证：

| 场景 | 必须观察到的结果 |
|---|---|
| 空范围凭据，身份仍是该空间成员 | 列表为空；直接读/写/消费均拒绝 |
| 合法单空间、通配、只读/读写组合 | 合法操作仍成功，不能靠一律拒绝过关 |
| 同键脱敏两次、同键改理由 | 1 审计、1 事件、同 ID；改内容 409 |
| 在审计/事件/幂等记录写入阶段注入失败 | 内容、索引、审计、事件、结果引用全部回滚 |
| 超过默认分页数的修订被脱敏 | audit 覆盖完整 revision 集合 |
| poll 后成员权限版本改变，再 ack | RESYNC_REQUIRED，游标和 batch 未被确认 |
| 合法 ack、同 batch 重试、伪造位置 | 保持正确进度和现有拒绝语义 |

出口：T04/T05/T08 通过，正式回归覆盖上表；不要用“新建了一张表/类”作为完成证据。

## R3-B：固定操作结果，与当前状态和旧库格式分开

覆盖 R3-F03/F04，主要入口为 idempotency、storage、bootstrap/migrations、CLI init/serve。对应 T01/T02/T03/T06/T07/T11。

必须实现：

1. **先列出实际返回类型。** space.create/patch、thread.create/patch、post.create/revision/withdraw、relation.create/resolve/reopen，以及 redaction，不是全部都返回 `{entity,...}`。当前直接返回 Thread/Post/Relation 的操作会掉入完整 JSON fallback。以明确 operation/result kind 定义可判别引用 schema，类型系统穷尽处理；未知引用版本安全报错，不能原样返回任意 JSON。
2. **保存可重建的固定结果。** 引用记录包含对象 ID、操作版本/修订及必要关联 ID。resolve/reopen 根据 resolution_id 读取真正的 RelationResolution，重试保留相同 id/action/version/reason_ref。不能保存了 ID 却从记录里读取不存在的 resolution 对象。
3. **固定结果不偷换为最新版本。** thread 创建/修改、relation 解决/重开、space 修订、post 修订在后续变更后，原键仍对应原操作。需要不可变版本实体时只增加最小持久结构，再让幂等记录引用它。允许更新的当前生命周期/脱敏投影与原操作版本分清楚并同步契约；不以返回最新对象掩盖历史不可恢复。
4. **先迁移旧结果，再按新 schema 读取。** 明确解码 fa1b35c 的完整响应、c4f041f 的 `$ref` 和直接实体 fallback。旧 space.revision 是对象，要取其 revision 数字；不得交给 SQL 驱动猜。已有初始帖子、修订、关系处理记录均覆盖。缺少必要历史时明确拒绝/隔离并给恢复说明，不伪造成功，不覆盖真实业务数据。
5. **真正区分初始化、升级、故障恢复。** 旧库已存在管理员和合法凭据时，新增元数据属于迁移，不能再发管理员 token。初始化完成与当前管理员凭据是否被撤销是不同事实；不能因凭据变化自动重置初始化状态。空白库初始身份/凭据/密钥/完成标记同事务；损坏旧库走明确的受控恢复流程。
6. **所有入口共用版本预检。** init、serve 和业务打开库路径在执行 DDL/DML 前检查 schema；高于支持版本、未知旧结构均拒绝。`serve` 必须在监听前拒绝。对拒绝的库不新增表、不写实例密钥/版本标记。不能只把检查加到 bootstrap，却让 serve 绕过。
7. **有序迁移和单一 DDL。** 支持并说明 a6c437d、fa1b35c、c4f041f fixture 的升级路径，不能仅插入 version=1。统一 schema.sql/schema.ts 来源，增加实际迁移版本与完整性检查。旧缓存转换后不保留正文/摘要/标签副本；即使读兼容已遮盖内容也不等于迁移完成。损坏旧 JSON 不得 catch 后跳过并继续宣称成功。
8. **实例材料和生命周期。** 使用正式存储端口或组合根方法读取持久密钥；无法读取时应报错，不静默生成不可持久的临时 secret。保持目录锁、正常关闭顺序、第一次 init 原子性已修复行为；所有异常路径先关闭本次打开的 DB/服务再释放锁。不得删除现有用户数据库作为迁移办法。

验收矩阵，不只检查请求状态码：

| 维度 | 最低覆盖 |
|---|---|
| 操作 | 上述全部已实现幂等操作，包含直接实体返回类型 |
| 重试 | 立即同键重试、后续修订后重试、关闭重开后重试、提交成功但响应丢失后重试 |
| 结果 | 固定 ID/版本、完整关联记录、正确响应 schema、当前脱敏/授权投影 |
| 冲突 | 同目标改内容 409、不同目标不串用、两个竞争写请求只有合法结果提交 |
| 旧数据 | 三个已有基线 fixture；旧完整 JSON、嵌套 initial_post、旧 space revision 对象、新 $ref、损坏记录 |
| 迁移 | 业务数据保留、凭据不增发、旧正文副本清除、重复迁移无变化、失败回滚、close/reopen |
| 版本拒绝 | init 与真实 serve 均拒绝 version=999，拒绝前后库的逻辑结构/数据不变 |

并发测试使用屏障/独立请求或必要子进程；顺序两次调用不能报告成竞争测试。升级 fixture 应标明生成来源与版本，不能把本轮构造的逻辑 fixture 冒称完整历史二进制演练。至少提供一条可由别人复跑的旧库升级命令与结果摘要。

出口：T01/T02/T03/T06/T07/T11 及矩阵通过；迁移记录能证明确实升级，不能只把旧格式继续留在数据库而称完成。

## R3-C：取消全链路、公开契约和真实交付记录

覆盖 R3-F06 与上轮未完成的契约/证据要求。对应 T09/T10。

必须实现：

1. **Signal 贯穿每一层。** adapter→callTool→getContext/createPost 等 wrapper→request→fetch，使用共用 RequestOptions 或等价明确接口。不能只在 callTool 的开头读一次 signal。8 个工具各分支均传入，不复制业务逻辑。
2. **完整取消生命周期。** 请求开始前、等待响应头、读取 body、重试退避四个阶段均可取消；取消后尽快 reject，不启动下一次请求。timeout 包含必要的正文读取阶段。监听器和定时器在 finally 清理，不能在收到响应头时过早移除。JSON 读取失败/abort 不得被 `.catch(() => null)` 转换为 HTTP 成功。
3. **取消不伪装回滚。** 服务端可能已经提交，重试继续用原幂等键；用户取消和可重试网络超时区分，保持最多有界重试和既有业务错误码。
4. **Pi 契约证据。** 核查 [Pi 官方 Extensions](https://pi.dev/docs/latest/extensions) 与链接的官方类型，固定实际 SDK 版本/commit，使用官方 ExtensionAPI 编译，不能复制一个本地同名宽松接口冒充。验证 execute 抛错、命令输出、无 UI 场景及本轮取消链；宿主未运行就保留 not_tested。如果缺依赖无法做官方编译，明确记录缺口、撤回相应通过声明，不用“未调用付费模型”解释类型检查缺失。
5. **已实现 HTTP 契约清单。** 将 admin/relations/events 等已启用路由的 schema 接到实际验证；body/query/params/header 的要求与 docs/04 一致。保留正常 HTTP 头，不把标准 Host/Accept 等误拒为未知属性。坏类型/枚举/额外业务字段返回稳定 4xx，合法客户端操作成功。同步公共 protocol、OpenAPI 与 CLI/MCP/Pi 映射。未来接口另列设计，不强行实现 M2–M7。
6. **交付证据要可执行。** 固定受支持工具链并提供 CI 配置、锁文件安装方式；`packageManager` 等机器约束与文档一致。对 CI 使用的命令本地实际运行，没跑远端 CI 就不能说远端 CI 通过。lint 若仍等于 tsc，明确记录这一点，不必为了检查数量引入新工具。

取消验收必须使用受控 barrier：先确认 fetch/正文读取/退避已经开始，再触发 abort，并断言 Promise 拒绝、fetch signal 被取消、请求计数不增长；不得仅传一个已取消 signal。至少验证一个实际 Pi 注册工具和一个底层 HTTP request。必要时用本机临时流式 HTTP fixture 验证真实 body 中断，不依赖模型服务。
