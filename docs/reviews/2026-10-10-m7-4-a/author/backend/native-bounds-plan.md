# Native probe bounds — proposed implementation, pending root decision

No source/runtime change. v9 and the original failures/guard/core receipts remain preserved. Current defect is real: the 60s timer is cleared at finally entry, app.close is unbounded, and D's external Popen.wait has neither a timeout nor authority over a detached native group.

## Smallest reliable structure within the existing probe file

Use one supervised worker, implemented in the same owned `claude-check-probe.mjs`; no additional product/source file or host flag. Public CLI remains exactly --binary/--output. Public exported `runClaudeCheckProbe({binary,output})` also invokes the supervisor, so programmatic users get the same bounds; the current body becomes a private worker function, never a publicly callable unbounded bypass. Module import remains pure: only the existing direct-entry check starts work. The supervisor forks the same file with the same public arguments and a real IPC channel; an actual forked entry waits for a typed finite bootstrap IPC message instead of choosing a role through a test-specific environment variable. It does not mutate HOME/CODEX_HOME/parent env.

Supervisor creates/canonicalizes the 0700 privateRoot and owns it through worker actual close. Worker receives only that exact root, fixed binary and intended output via private IPC, validates canonical ownership/mode, derives all policy/config paths there and never creates another root. It returns only the v9 safe report/error projection through bounded IPC; raw native output remains worker memory and is never forwarded. Supervisor publishes the new0600/no-clobber report after real worker close and final cleanup. The original error remains preferred over timeout/cleanup errors; bounds failure always marks failure, not successful cleanup.

## Concrete deadlines and teardown

Retain a 60s absolute total deadline; do not clear it on finally entry. Give normal work at most 50s, reserving the remainder for teardown. These are smaller internal budgets, not a larger host/test timeout or a change to tool inputs. All waits use the shared absolute deadline; an operation race only rejects, never certifies a cleanup. Worker teardown: stop issuing controls, original SDK/native cancellation, TERM the registered native group; after at most 1s send KILL if needed, then await/verify actual child close. Drain the existing app business leases (beginDraining + waitForIdle and assert activeCount=0), then destroy only tracked own accepted sockets and await their actual closes, finally await original app.close. Only actual completion sets flags. Own forbidden HTTP server, DB and root cleanup are independently attempted; DB success is not claimed as proof that app closed.

If any worker wait cannot settle before the total deadline, supervisor performs emergency group termination, then worker termination, waits real worker close, and removes its exact privateRoot. Failed business/app close stays false even if emergency process cleanup succeeds. Supervisor itself has a finite outer deadline (suggest 65s: 60s total plus finite emergency close allowance); inability to verify actual close is a failed diagnostic, never a success. D's runner separately uses a finite timeout slightly beyond that and reads only the exact invocation registry before TERM/KILL; no unbounded Popen.wait or system-wide process search. All group kills are restricted to positively registered own leaders, never process-wide/all-host/global-agent shutdown.

## Registering native/MCP ownership rather than guessing

Native is spawned detached as now. Worker registers its returned child PID/PGID with the supervisor immediately through private IPC, before awaiting controls; supervisor acknowledges registration before the worker proceeds. A spawn error is handled; PID presence alone is not reported as successful Claude initialization. Track actual native spawn and close separately. Supervisor keeps the ownership registry even if the worker later fails.

MCP containment must not be inferred solely from “Claude usually inherits its group.” Proposed narrow confirmation: replace only the trusted local MCP command launcher with a generated, fixed trusted launcher under privateRoot (no downloaded/forum code). The launcher writes its own PID to a single private registration file before importing the fixed repository MCP entry, then waits for an acknowledgement. Supervisor verifies that exact PID's PGID with a narrowly targeted OS query and requires it to equal the registered native PGID; only then acknowledges and allows MCP to initialize. No scanning of unrelated processes, raw argv, user configuration or accounts. On mismatch, fail closed before importing MCP; do not allow an unregistered second detached group. This keeps the native/MCP tree under one positively verified own group and avoids promising cleanup based on an assumption. The launcher has its own bounded registration wait and exits on missing acknowledgement.

This last launcher/PGID step is the one explicit implementation choice requiring root approval: existing native control source has not proved MCP never detaches. If root has fixed-source proof plus independent observed PGID evidence sufficient to establish same-group ownership without a launcher, reuse it and omit this extra step; do not assert that proof exists here. It changes only probe-owned transient fixture command wiring, not product MCP protocol/permissions or OS policy strength, but should not be silently implemented under a diagnostic-only instruction.

## Parent/worker death and D supervision

IPC disconnect is a worker abort signal. If supervisor dies, worker enters the same teardown, and its independently installed total watchdog remains armed. This covers normal disconnect and an unresponsive parent; it is not a blanket claim that arbitrary kernel/process failures can never leave a process. D creates its own invocation-owned control directory/registry and keeps exact supervisor/worker/native IDs from safe IPC or atomic private registry records; an external deadline may terminate only these registered groups, then await actual exits and verify exact owned root absence. Registration/ack must precede work, so external cleanup never relies on a broad process hunt. A registry must not contain tokens/settings/raw output. D evidence distinguishes graceful close, TERM/KILL emergency cleanup, and unverified close.

No policy changes, help/model/prompt calls, extra public flags, tool inputs/authorization/assertions, shared exports/fixtures/Pi code or product Fastify options. Preserve real two-write/six-read assertions and no-ACK; do not move the poll entry/cancel trigger. Root selects the design before implementation; B reviews source and D alone runs the bounded experiment.
