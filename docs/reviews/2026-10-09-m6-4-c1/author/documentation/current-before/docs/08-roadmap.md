当前入口：[M6.4-B评审CLI与九工具](reviews/2026-10-09-m6-4-b/README.md)。十二评审CLI、九个canonical工具及固定Pi/dsh有限接入已接受，schema5不变；816项/128文件为首811成功+5失败后五文件30/30复验的有限组合，不是最终源码一次全套exit0；新13全过，最终build/type/lint0，current25原选25/25（6原+19既有adapter、无新adapter）。 Web正式评审进入下一[C1任务书](reviews/2026-10-09-m6-4-b/planning/m6-4-c1-task.md)，C2公共检索/知识投影与M7真实checks/receipts仍待。

所有包按编号顺序推进。可以在阶段内处理无依赖任务，但并行 Agent 需用户授权，并先划定文件所有权。每包结束更新真实进度记录，不提前勾选后续验收。

## 总体依赖

```mermaid
flowchart LR
  M0[契约与版本冻结] --> M1[身份与讨论]
  M1 --> M2[证据与知识]
  M2 --> M3[可靠消费与运维]
  M3 --> M4[四类客户端接入]
  M4 --> M5[Web 与 v0.1]
  M5 --> M6[正式评审]
  M6 --> M7[外部检查与 v0.2]
  M7 --> M8[真实协作评估]
```

以下不是工期承诺。建议把每个子项作为独立 issue 或可审阅提交，而不是一次生成整个仓库。

## M0 — 建立可实施基线

输入：本目录全部设计；重点 docs/03–05、integrations/dsh.md、integrations/pi.md。

任务：

- M0.1 确认安装/可测试环境；只读记录 dsh、Pi、Codex、Claude Code 版本和官方说明 commit。缺少客户端时先标 not_tested，继续无模型核心开发。
- M0.2 建立 pnpm/TS strict、protocol/core/server 最小骨架、格式与 CI；锁定运行时、SQLite、MCP/Pi SDK 版本。
- M0.3 定义实体与全部公开操作的 schema、错误码、状态枚举；生成 OpenAPI 草案及工具目录。用本文请求示例校验，先解决互相冲突的字段。
- M0.4 用技术探针验证 SQLite FTS5、中文短查询、驱动安装，以及官方 MCP SDK 与目标宿主的握手；无业务副作用。
- M0.5 记录许可/发布名称等未决项；生成 `docs/progress.md`，列出每阶段状态和验证链接。

出口：干净安装能 build/typecheck，契约可解析，版本/风险/决定有记录。不得以探针代替完整产品。

## M1 — 两个身份完成讨论闭环

输入：冻结的协议；docs/02、03、04、07。

- M1.1 迁移、数据目录锁、bootstrap、actor/token/membership 与统一授权。
- M1.2 空间/规则修订、session、主题、帖子及修订、精确引用。
- M1.3 幂等记录、事件追加、乐观并发、撤回、异议 resolve/reopen 的权限。
- M1.4 HTTP 垂直场景：A 发提案，B 引用该版本提出异议，A 发布新版，旧引用不变化。

产物：可运行 server 和 HTTP 示例。验收 T01、T02 写事务部分、T03、T04、T09。出口：崩溃/重试/并发都不能绕开不变量。

## M2 — 证据与可检索记忆

- M2.1 流式附件上传、哈希、配额、下载授权和孤儿清理。
- M2.2 类型化 proposal/claim/failure/summary 校验与知识视图。
- M2.3 FTS5、中文 1/2/3 字、标签/主题过滤、分页、脱敏投影移除。
- M2.4 context 输出预算、来源更新提醒、读取检查点。

产物：失败检索和上下文接续演示。验收 T05、T06、T07 和 D01 步骤 1–3。出口：新客户端仅凭论坛材料找到已有反例，并看到适用范围。

## M3 — 可靠消费、备份和恢复

- M3.1 subscription/consumer/batch，单批次 poll/ack、过滤扫描、重投、ACL epoch。
- M3.2 共用 client，超时、取消、有界重试、request_key 持久化接口。
- M3.3 脱敏、离线备份/恢复、结构化导出/新实例导入、迁移演练。
- M3.4 配额、限流、结构化日志、健康检查和 graceful shutdown。

产物：重启服务及客户端后恢复未确认事件的脚本，备份恢复指南。验收 T02 完整、T08、T12、T13。出口：任何读操作不能偷偷推进 ack；备份能在新数据目录恢复。

## M4 — 四类 harness 的第一产品接口

- M4.1 CLI 命令与稳定 JSON 输出/退出码；附件管理、凭据操作与诊断。
- M4.2 stdio MCP 桥，公用工具 schema，stdout 清洁，协议兼容测试。
- M4.3 dsh 官方 MCP 配置与实际工具发现，测试探测进程、重启、凭据隔离；提交完整经验证 patch 示例。
- M4.4 Pi 原生扩展，共享 HTTP client，工具/命令、会话切换和资源清理；不默认启用 RPC 控制。
- M4.5 Codex、Claude Code 的配置和相同端到端场景；更新 compatibility 记录。

验收 T10、T20、D02。出口：四者的实际版本/已验证路径明确，未安装的客户端必须保留阻塞项，不能把模拟适配测试当实测认证。缺客户端不阻断其他工程包，但阻止“全客户端支持已完成”的发布声明。

## M5 — 人类界面与 v0.1

- M5.1 同源认证会话、空间/讨论/失败/搜索/证据/修订页面。
- M5.2 空态、错误态、内容过期、无权限与断线提示；键盘和窄屏可用。
- M5.3 单服务容器、持久卷、最少配置、使用教程、D01 的 v0.1 演示（步骤 1–4 及非正式汇总）。
- M5.4 20 客户端并发基准、发布资料、干净环境安装/恢复演练。

验收 T01–T13、T20 的已实现接入项与 D01 的 v0.1 部分。v0.1 的正式评审入口应显示模块未启用，而不是伪造已完成状态。此阶段能供日常协作试用，尚未完成用户希望的正式研究评审目标。

## M6 — 可配置独立评审

- M6.1 review 模块迁移、策略 schema、材料 manifest/hash、贡献者排除。
- M6.2 固定名单、封存提交、独立性声明、私有附件和全入口隔离。
- M6.3 reveal/finalize/cancel、异议阻塞、材料/策略修订失效与事务竞态。
- M6.4 HTTP/CLI/MCP/Pi 评审动作和 Web 页面；保留 informal review 区别。

验收 T14–T17、T19。出口：两个不同合格身份能对同一快照独立提交，任何单身份双 session、自审、缺项、旧版批准均不能通过。

## M7 — 外部验证与 v0.2 完整交付

- M7.1 check run/receipt、受限 verifier、版本和配置绑定、重放冲突与重跑规则。
- M7.2 提供一个无模型的本地外部验证器示例；它在论坛进程之外运行固定的 D01 检查，不执行任意论坛指令。
- M7.3 贯通 D01 的快照、两份初评、验证、最终决定及“后续发现新问题”的演示。
- M7.4 完成 v0.1 → v0.2 迁移、导出/恢复、安全回归、四客户端兼容记录；形成 release checklist。

验收 T01–T20、D01/D02。完整交付包含源代码、配置、迁移、schema/OpenAPI、四客户端指南、测试报告、演示、许可和已知限制。未完成外部检查或真实客户端认证的部分必须列明，不能宣布整体通过。

## M8 — 证明产品价值，独立于 CI

依据 docs/09 E01 准备固定题集、评分器和预算。真实模型运行由用户提供/授权账号和预算，论坛不保管模型密钥。先小规模试验，再做对照与消融；允许得出“论坛在这类任务不划算”。

产物：原始脱敏轨迹、配置、数据和图表、成本、失败/部分进展、置信区间及局限。不能用一段表演性聊天证明提高科研产出。

## 每包统一 Definition of Done

行为符合当前 schema；权限和错误路径已测；迁移可复现；相关示例不漂移；未引入秘密或未经授权的外部调用；记录测试命令及结果；本包能由另一位开发者在干净环境复跑。必要时先修复再进入下一包。
