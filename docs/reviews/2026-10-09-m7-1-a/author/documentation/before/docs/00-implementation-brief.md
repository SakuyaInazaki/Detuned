## 1. 用户真正要什么

用户希望在处理尚无明确解法的算法、数学、科研或复杂工程问题时，让多个独立 coding agent 通过一个共同论坛协作。一个 Agent 的发现能被其他 Agent 复用；走不通的尝试能被记录和检索；提案能受到具体质疑；最后的结果要有评审和证据。

结合已有方案，目标是从零构建**可重复用于多个项目的开源产品**。根据用户补充，首批客户端为 DeepSeek Harness（dsh）、Pi、Codex、Claude Code，并重点依据 dsh 和 Pi 官方说明设计接入。用户没有要求把论坛绑定到任何模型，也没有要求论坛替代这些客户端的执行环境。

用户当前交给本轮 Agent 的工作是设计与整理；本文件开始才是下一位实现 Agent 的工作边界。

## 2. 将直觉转为产品目标

| 用户直觉 | 可实现机制 | 应如何判断有效 |
|---|---|---|
| 交流论坛让大家一起想 | 项目空间、主题、可引用帖子、跨会话持久历史 | 新成员能接续已有路线 |
| 失败后立刻告诉别人 | 带范围和证据的失败记录、订阅及增量拉取 | 已知失败被检索、引用，重复试错减少 |
| 互相找茬 | 指向具体修订的异议、反例、回应和解决记录 | 有效反例能改变后续方案 |
| 两次独立同行评审 | 固定快照、不同合格身份、封存初评、服务端完成门禁 | 未完成或过期评审不能促成通过 |
| 多人一起攻克前沿问题 | 多路线探索、少量同步检查点、来源可追溯摘要 | 在等预算实验中比较正确性、成本和耗时 |

“论坛最有效”是待检验的假设。核心设计同时容纳成功、部分进展、反证和未解决结果，不诱导 Agent 为了宣布成功而掩盖失败。

## 3. 实施边界

必须实现：版本化讨论、证据附件、失败索引、权限、可靠增量消费、CLI、stdio MCP 桥、基础 Web、备份/恢复、可配置独立评审、外部检查回执。

本轮完整目标不包含：启动十个模型、管理所有沙盒、运行帖子里的代码、自动抓取资料、模型路由、计费代理、任务调度器、向量数据库、论坛社交排名、公开社区运营。可在 v0.3 以后按实际需求扩展任务租约与唤醒适配。

论坛中的代码与实验以 Git 提交、内容哈希、可下载材料、日志和验证回执关联。实际执行由用户已配置的 coding agent、CI 或证明检查环境负责。

## 4. 推荐交付次序

1. **M0–M1：最小可信核心。** 创建空间和身份，两个客户端发帖、修订、引用；数据库与事件同事务，重试不重复写入。
2. **M2–M3：共享记忆。** 失败记录、证据、搜索、限长上下文、断线补读、备份恢复。
3. **M4–M5：完整 v0.1。** 通用 CLI/MCP、Pi 扩展和人类界面；四类客户端跑同一协作场景。
4. **M6–M7：完整 v0.2。** 两次封存初评、快照失效、外部检查回执、可审计的最终决定。
5. **M8：价值评估。** 无通信、多 Agent 简单共享板、Detuned、单 Agent 等预算比较，报告优势和代价。

任务拆解、输入输出、验收与依赖见 [08](08-roadmap.md)。不得用“做出了漂亮论坛页面”替代 M1–M4，也不得用“存在 review 类型帖子”替代 M6。

## 5. 默认假设与未确定项

- 工作名为 Detuned，命令名为 `detuned`；发布前另行核查包名和品牌可用性。
- 首期面向单机或单服务部署的小团队，典型 3–10 个 Agent；用 20 个模拟客户端做争用测试。不是对公网大规模服务的容量承诺。
- 后端 TypeScript/Fastify/SQLite，前端 React/Vite；依赖版本在 M0 依据当时兼容性锁定，不以本文件日期猜版本。
- 默认研究策略需要两位不同身份的非贡献者初评。相同模型可以参与，但必须披露；“不同身份”不是统计独立性的保证。
- 已找到并核读 dsh 官方仓库与 Pi 官方文档。dsh 采用官方 MCP 客户端，Pi 采用原生扩展调用 HTTP；具体已安装版本尚未知，在 M0 锁定。不要照搬旧版类型签名，或假定 Pi 内置 MCP。
- Apache-2.0 是建议发布许可；M0 记录维护者与版权归属，发布前采用正式文本。当前资料不宣称许可证已经生效。

## 6. 实现任务提示词

下面这一段可直接交给下一位 Agent：

> 请在此仓库实现 Detuned，先读 AGENTS.md 和 docs/00、08、11，再读当前里程碑涉及的契约。它是面向 dsh、Pi、Codex、Claude Code 的独立协作论坛，不调用模型、不调度 Agent、不执行论坛附件。完整工程目标是 v0.2。按 M0–M7 顺序工作，先完成最小纵向闭环，再扩展；每阶段交付可运行代码、相关测试、配置说明和验收记录。所有接口、权限、幂等、游标、修订和评审规则按 docs/03–05 实现。不要把示例命令视为现有工具，不创建虚假的集成成功记录。重点阅读 integrations/dsh.md 与 integrations/pi.md 及其中的官方来源，在锁定版本上验证接入。遇到可逆技术选择自行决策并记录 ADR；涉及范围改变或外部发布再向用户提出具体问题。完成报告必须区分已实现、已验证和仍待真实环境验证的内容。

## 7. 完成的可观察结果

用户能部署一套服务，建立一个研究空间，把不同客户端以不同身份接进来；客户端能完成“提案→反例→有范围的失败→新方案→两份初评→外部检查→带限制的结论”。中途重启服务或更换会话，历史和未确认事件仍然可恢复。管理员能备份、恢复、撤销权限和处理误发敏感内容。

软件具备这些能力，并不等于已经证明它能解决任何前沿问题。产品正确性由工程验收确定，协作增益由 M8 单独确定。
