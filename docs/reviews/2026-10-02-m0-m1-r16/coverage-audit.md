## DDL 结论分开表述

1. `schema.sql → SCHEMA_SQL + 3 个 MIGRATION_DDL 常量 → bootstrap` 已成立，隔离构建也通过。这一部分无需重写。
2. storage.test.ts:172 的新建/升级 parity 比了 table_info、foreign_key_list、index_list、index_xinfo 与 FTS SQL，确实比 R15 完整；当前索引都是 partial=0，没有比较任意 WHERE 谓词文本。
3. 运行时结构预期依旧手写，V1 直接过滤 V2。生成/同步脚本未覆盖该对象，类型也不表达 collation/desc/FTS 列索引标志。不能把建库 parity 当成描述来源约束。
4. 生成脚本剥除整行 SQL 注释后做同步比较。应说规范化 SQL/抽取片段一致，不能说原文件字节一致；冻结的历史 fixture 与 archive 则必须保持原字节。
