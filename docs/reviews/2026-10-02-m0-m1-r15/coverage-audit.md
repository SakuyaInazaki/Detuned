## DDL 与文字勘误

1. SQL→常量的生成/检查已运行，通过隔离编译及移走源目录后的导入验证；这部分不再是仅手工相等检查。但 bootstrap 三处 CREATE TABLE 仍单独维护，结构描述也未受该生成脚本约束；完整单源要求尚未完成。
2. 常量名为 `SCHEMA_SQL`，不是报告的 `CURRENT_SCHEMA`。脚本先剥除整行 SQL 注释再比较，是规范化后的相同，不是两个原文件字节一致。
3. 正式结构 parity（storage.test.ts:172）仍只比 table_info、foreign_key_list、index_list；后者不包含完整索引定义。新结构验证器使用 index_info，也没有索引 partial/predicate 或 FTS 模块检查，Y01 已复现。
4. “类型亲和性”与当前实现不相符：实际直接比较声明类型的大写字符串。描述应从实际规则出发，不额外承诺未测试的兼容格式。
5. 11 族实际为 space.create、space.patch、thread.create、thread.patch、post.create、post.revision、post.withdraw、relation.create、relation.resolve、relation.reopen、admin.redaction。移除本轮报告中 decision.publish/evidence.attach/export.create 的错误验收声明。
6. G/H/J/K 在本轮最终归档中的命令 ID 为 14/15/16/17，不是勘误段的 12/13/14/15。根 README 与进度文件末尾的交付节称 B.4-3 完成，但进度文件顶部仍是 R14、阶段表仍称“下一任务，尚未实现”；以新独立结论统一入口，原交付声明保留。
