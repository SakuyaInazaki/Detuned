## R2.1：初始化、迁移和目录生命周期

对应 R2-F06，并为 R2.3 的历史幂等记录升级提供基础。

实现行为：

1. bootstrap 使用明确的实例初始化状态，不能凭“有一个 kind=human 的 actor”判定初始化完整。管理员身份、初始凭据、实例必要材料在事务内创建，失败应全部回滚。
2. 文件库关闭重开后可从未完成初始化重新开始；重复正常初始化不额外创建管理员或泄露/重发原始 token。对于已有“有 human、无初始凭据”的损坏库，提供受控、可审计的恢复指引或本地恢复入口，不能静默接管任意现有用户身份。
3. init 与 serve 共享同一目录锁约束；serve 对未初始化库默认报清晰 init 指引，不生成后丢弃一次性凭据。停止时先停止接收请求、结束相关资源、关闭 DB，再释放锁。
4. 保留已实现的死 PID 基本恢复，但检查锁文件归属，不能无条件移除活进程锁。不要通过仅检查 lock 文件存在与否模拟完整生命周期。
5. 建立实际按版本执行的迁移及事务/完整性检查，明确支持从 `a6c437d` 无版本记录库和 `fa1b35c` 版本 1 库升级。只有确认相符的旧结构才能登记 baseline；未知/更高版本要明确拒绝。迁移不得删除用户业务数据。DDL 使用单一事实源，避免 bootstrap 与迁移各有不一致的建表脚本。

验收：把 S11 转为正式文件库故障测试；覆盖正常重复 init、凭据插入失败、关闭重开重试、未知版本拒绝、旧库升级、活锁拒绝和进程异常退出后恢复。至少一个真实 CLI init/serve 生命周期子进程测试。不要只检查 migration 表有一行。

## R2.2：统一授权、checkpoint 和事件归属

对应 R2-F02、R2-F05、R2-F07。

实现行为：

1. 在 core 统一定义每类操作要求的 capability，不靠 `minimumRole !== observer` 推断全部能力。读必须有 read，写必须有 write；admin 的能力含义明确列出，不让空数组获得隐含权限。当前 membership、凭据空间范围、对象可见性仍必须成立。
2. `/spaces`、`/me` 以及内容读取使用一致范围语义。明确 `allowed_space_ids=[]` 与 `['*']` 的差异，建议前者不允许任何空间；增加 ADR 和迁移说明，不能静默放大旧凭据权限。未知角色/能力拒绝，撤销/禁用在请求和最终写事务生效。
3. 消除生产路径中的公开固定 token secret。沿用 HMAC 时，每实例生成随机密钥，安全持久保存并在重启后复用；业务客户端不能读取。测试可显式注入专用密钥，生产 `serve` 必须走真实实例材料。也可选数据库随机句柄，但只能实现一套有明确迁移策略的方案。
4. checkpoint 绑定用途、actor、space、有效期与读取高水位；使用整数且不能超过服务端可接受高水位。context 内容与 checkpoint 高水位来自一致读取快照。增加实例/权限失效语义的明确判断，检查点不能跨身份、跨空间或被旧公开密钥伪造。旧不安全 checkpoint 统一失效并给重新同步指引。
5. ACK 推进继续取服务端持久 batch，不信任客户端 through_seq；在当前权限/ACL epoch 下核验。poll/ack 不应在撤权后继续成功使用旧 batch；重复合法 ACK 成功、旧 ACK 不倒退。不要扩大成长轮询或整个 M3 实现。
6. thread_ids 筛选能识别 relation.created/resolved/reopened。明确并记录“源/目标任一关联线程命中”的规则或规范认可的等价规则；两端都在订阅线程时必须投递。禁止为实现过滤把正文复制到事件。保持过滤扫描高水位和空匹配批次的 ACK 语义。

验收：S04/S05/S06/S07 对应正式测试；加正常签发与同身份使用、服务器重启仍有效、过期/错身份/错空间/旧固定密钥/未来序号拒绝；token 读写能力与角色组合；权限变更后的旧 batch；thread/post/relation 的命中与排除。使用可控时钟或显式过期数据，避免慢等待。

## R2.3：目标感知的幂等引用与原子脱敏

对应 R2-F01、R2-F03。

实现行为：

1. 盘点当前全部已实现幂等写操作，统一 operation 的资源范围。resolve/reopen 必须纳入 relation_id；thread/post 等已修复入口保持一致。同目标同键同内容返回同一操作结果，不同内容冲突；不同目标不能返回另一个对象的成功。规范化请求 hash 包括实际影响请求身份的字段，不遗漏 URL 目标。
2. `result_ref` 只存重建结果所需的对象 ID、固定修订/操作版本、结果类型等引用元数据，禁止继续缓存完整 post/revision/initial_post 正文与标签。普通首次响应仍可含正常业务数据；数据库中的持久幂等记录只留引用。
3. 重放先重新鉴权，再根据固定引用重建响应并应用当前脱敏/可见性。重建不能悄悄换成最新修订：返回第一次操作对应的版本，允许契约规定的 tombstone/脱敏响应。目标丢失、撤回、脱敏、权限失效有确定错误或投影规则。
4. 迁移已有完整 JSON 缓存，包括嵌套 `thread.create.initial_post`。在临时旧库 fixture 上验证保留对象/版本/幂等关系，同时清除正文副本。无法解析的旧记录不得继续原样回放或默默吞异常；给出保守拒绝和可诊断策略。
5. 将 redaction 放到 core 服务。权限/归属、所有目标修订、可见内容字段及 tags、索引移除、审计、脱敏事件、幂等结果作为同一事务处理。审计记录实际影响的 revisions，不能固定 `[1]`。同键重试不重复审计/事件。
6. 建立统一的可见内容投影，被脱敏对象不能经 revisions、thread/initial_post、context、搜索、幂等重放重新出现。区分允许保留的引用/哈希与必须隐藏的内容。不要继续扫描/替换任意 JSON 字符串作为主要设计。

验收：S01/S02/S03/S10 对应正式测试；覆盖 initial_post 与普通 post、至少两次修订、tags、同键重放、已有缓存迁移、失败触发器导致全回滚、重放不增加事件；resolve 和 reopen 两个操作都测两目标。补两个并发冲突写入只有一个成功的有效测试，以及提交成功但响应丢失后重试恢复。至少有文件库 close/reopen 验证；不可仅顺序调用后声称验证并发。

## R2.4：恢复合法 CLI，补齐已实现接口的严格契约
