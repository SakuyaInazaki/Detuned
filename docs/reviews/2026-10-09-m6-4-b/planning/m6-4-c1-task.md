## Catalog contract
GET /api/v1/spaces/:space_id/posts/:post_id/review-requests. Strict query: limit integer1..50/default20; max_bytes4096..65536/default12288; opaque cursor nonempty<=4096. Historical all-round directory, round DESC; positive unique round seek below last round. Existing UNIQUE(space_id,target_post_id,round) supports selection, no new index or collection sort.

Signed cursor binds version/purpose/actor/space/post/sort/last positive round/expiry. TTL86400s, continuation retains original expiry. Use existing TokenSignerPort and instance secret, implicit instance binding; no claimed ACL-epoch field. Each page current credential/space authorization in one readSnapshot, not a cross-page frozen set. Limit/budget may change on continuation; they are output controls, not filters. Malformed/expired/domain mismatch→400 VALIDATION_ERROR. Current target redacted rejects; other frozen material redaction permits safe status only, cannot recover manifest or sealed contents.

Return whole page {data:summary[],meta:{truncated,next_cursor:string|null}}. Summary contains request_id,snapshot_id,space_id,target_post_id,round,target_revision,created_at and original Status semantics phase/verification_status/current_validity/validity_reasons. Strict positive round/revision and date-time; descending unique rounds; no full roster, private evidence health or opinion preview. Entire UTF8 wire envelope {api_version:'1',request_id,data,meta} counted using existing serializer pattern. Remove trailing items to fit budget: truncated means byte truncation only; ordinary has_more may have cursor and truncated=false. Empty page cannot have cursor; first item plus required envelope cannot fit→422 QUERY_TOO_BROAD. Success and error private,no-store, including early Cookie rejection.

Module post-catalog-service opens outer readSnapshot and calls existing ReviewStatusService.getStatus per row; sqlite-storage readSnapshot reuses an existing transaction. Do not refactor status-service for optimization or create core→module dependency. Storage neutral limit+1/afterRound query only. Client getPostReviewRequests(spaceId,postId,query?,options?:{signal?:AbortSignal}) returns whole strict page via existing1MiB bounded JSON transport, validates all entries against requested space/post, count≤requested limit (default20), descending unique rounds and complete meta relationships. Target binding is not full wire byte-budget validation: exact envelope budget remains server serializer enforcement, with client transport retaining its actual1MiB bound. forum_read kind=review_requests uses id=post_id plus limit/cursor/max_bytes from same query schema and returns whole page unchanged. CLI review rounds <space-id> <post-id> forwards same strict controls and page. MCP/Pi registrations unchanged.
