Search results supply post_id/revision/thread_id/kind/title/summary/tags/snippet/created_at; read exactly their returned ref, not current. Failure/finding views add `report_kind:'author_report'`, formal review/check `not_enabled`, projected material and relation source/target refs/status/version. Failure material preserves attempt/category/assumptions/tested_scope/expected/observed/evidence_refs/evidence_state/evidence_missing_reason/ruled_out/not_ruled_out/retry_when; nullable historical values and `missing_fields` must be shown honestly. `open-questions` is a union of question records and open-challenge relation projections, not uniformly posts. See protocol/search.ts72–183. These are public research author reports, not formal approval.

All existing methods accept AbortSignal; Web uses one shared client's `browserSession.getCsrfToken`, cookie unsafe CSRF and current server authorization. Rendering extracted fields requires runtime narrowing at legacy any boundaries and plain text, not trust in TypeScript assertions. New write intent key/body must remain fixed on unknown result; no automatic ACK.

## Actual missing client/HTTP entry points, not UI design decisions

- No `getPostRevision`/`getPostContent` wrapper beyond existing `getPost` and `getPostRevisionContent`; naming an imaginary method is unnecessary. A safely byte-bounded revision **metadata-only inventory** does not currently exist in HTTP or client. Existing revision listing can be used only with its full-row cost honestly bounded/accepted; adding such an inventory would be a separate contract decision, not a thin alias.
- No list-artifacts or per-revision artifact-link inventory HTTP/client method is present. `artifact_ids` is a write input; revision associations live in storage. Known artifact IDs can come from actual structured evidence refs or a just-uploaded metadata response. Discovering all attachments of arbitrary revisions cannot be claimed from current metadata/content fields alone.
- No paged `getView` or server revision-diff API. Fixed versions can be read explicitly with existing segments; any comparison page must state what was actually loaded. No new ACL/approval/evidence-verification rule is needed or permitted in Web.

No next UI route, new API, library or feature priority is selected by this fact sheet.
