# 可复现协作小题

目的：验证信息复用和评审流程，使用已知结论，避免以真实前沿问题作为软件 CI 的不稳定依赖。

## 问题

有向非负权图，给定源点 s，返回每个顶点的最短距离；不可达用 null。要求支持零权边、平行边和相同距离。不要求论坛自己执行算法。

错误候选：按邻接表顺序遍历，一个顶点第一次被发现就固定其距离，不再更新。

```json
{
  "vertices": ["s", "a", "b"],
  "source": "s",
  "edges": [["s", "a", 10], ["s", "b", 1], ["b", "a", 1]],
  "expected": {"s": 0, "a": 2, "b": 1}
}
```

邻接边先列 s→a，所以错误候选可能固定 a=10，之后遇到 b→a 时不更新。失败否定的是这个错误规则，不是否定 Dijkstra。改进候选采用正确的松弛与优先队列规则。

## 证据包

实现阶段由演示生成器创建 counterexample.json、候选实现、固定测试脚本和复现说明，上传为 artifact，记录 SHA-256 与真实代码版本；本次设计阶段不生成假运行日志。

外部固定检查器至少验证上述反例、零权边、不可达点和不同邻接顺序；另在固定种子小图上与简单可信参考实现比较。候选测试不能改变评分数据或预期结果。性能不作为此场景验收标准。

## 演示角色与预期

A/B/C 分别扮演提出、找错、改进；R1/R2 为非贡献者；V 仅上传固定检查回执。各角色使用独立 token，实验可用普通脚本驱动，真实模型不是前置条件。

详细流程见 docs/09 D01。运行输出必须保存到实际 reports 目录，包含数据库事件、检索命中、版本与快照、评审封存检查、回执及最终状态。演示后添加新修订，展示旧批准不能覆盖新版。
